# APK 点击闪烁调查与修复要求

日期：2026-10-23。状态：调查与需求已交接，尚未实施、未打包、未完成真机验证。本轮用户明确要求只做报告断点，不修改本体代码。

## 现象与证据边界

多名用户反馈 APK 端“每点击一下部队，屏幕会随着明显闪动一下”“玩起来一卡一卡的，然后点一下闪一下”，其中有人表示原版不会。两张本轮附件只有聊天文字，没有本轮闪烁过程的录屏；APK 版本、设备及 WebView 版本尚未确认。因此不能据此判定是局部图标消失、整屏亮度变化，还是地图空白帧，也不能把卡顿和闪烁认定为同一根因。

历史证据见 [2026-10-21 顶部图标调查](APK_UI_FLICKER_20261021.md)。该报告记载：旧录屏有数字仍显示而部分资源图标短暂消失的帧；桌面模拟 no-store 与图片延迟确认了节点反复替换，但未复现相同空白帧。本轮只读取历史报告，未重新逐帧审核旧视频。历史局部图标现象不能自动解释本轮所谓“整个屏幕闪”。

## 用户指定的修复要求

1. 金币、工业、粮食图标在同一资源版本内固定不动：直接引用图片资源，初始化后保留同一个图片节点，不因点击、选中、busy、刷新或数值变化而清空、重建、重复设置 src、隐藏后再显示。不要人为加入缩放、透明度、亮度或淡入淡出反馈。
2. 做稳定的顶部状态栏，显示在地图及部队之上，不随地图移动、缩放或地图重绘而重建。置顶指游戏 HUD 层级；暂停、设置、加载和模态窗口仍须保持正确遮挡与交互，不能用无限提高 z-index 的方式盖住所有窗口。
3. 图标必须允许 Mod 修改。沿用资源解析/覆盖通道，不能把原版图片嵌死在代码、绕过 Mod 或永久缓存成不可替换资源。原版逻辑资源为 `ui/image_ui_hd/marker_money.png`、`marker_industry.png`、`marker_food.png`，当前由 `/content/` 提供，对应 `client/ui/image_ui_hd/` 内容目录。
4. 数值图形没有变化时保留节点和文字画布，不重新调用文字生成，不重设 canvas 宽高，不重复绘制相同内容。只有后端已提交的权威状态反映实际值改变，才更新对应数值区域；可以仅替换这个数值的文字子节点，不得连带替换图标或整行。
5. **不能写死操作名单。** 升级建筑、募兵、修要塞、训练、上运输船、解散只是示例，不是刷新白名单。回合收入、事件、交易、退款、技能、Lua、Mod 自定义效果以及未来新增动作，都必须自动走同一变化检测机制。

“固定不变”适用于正常游戏操作及同一内容版本。初始化、切换 Mod/资源版本、字体或必要显示参数变化属于显式失效边界：允许按依赖更新实际变化的图像/数字表现，但不得把每次点击或任意世界 revision 变化当成整栏失效。

## 建议实现边界（交给后续修复会话）

- 建立持久的状态栏骨架，将图标和数字容器分离。`refreshHud()` 即使继续被多处调用，也应做到数据未变则不操作对应 DOM/画布；按钮 busy/disabled 更新与资源数字更新分开。
- 以成功接收并安装的后端权威状态为依据，逐字段比较 money、industry、food 等显示值；不要在前端根据动作名猜加减，不要在请求发出或点击时提前刷新资源。若已有通用变更通知可使用，但通知后仍需比较实际显示值，不能只看世界 revision。无需为本项强行引入新的服务端推送体系。
- 保留场景、会话、所显示势力、Mod/内容版本及显示参数的必要作用域。读档、重开、切局、本地多人切换不能复用到错误势力的数据；旧请求不能覆盖新会话的显示。同一数值可以保持同一数字节点，身份或资源依赖变化则按实际依赖刷新。
- 操作失败、取消、过期 revision、只选中或重复安装同一状态，不应引起资源图标/相同数值重建。批处理/快进允许只刷新真正展示的已提交结果，不伪造中间资源数值。
- Mod 切换及同名图片更新必须使资源缓存正确失效。若采用缓存头优化，先核实现有带版本路径与可变别名语义；不得把未带版本的 `/content/` 全部设置永久缓存。动态 API 仍需保持原有状态语义。此项是辅助优化，不能代替节点复用。
- 必须换图时尽量预加载/解码后切换现有 img，避免先清空可见图像；异步加载结果要校验当前资源版本，防止旧 Mod 的图晚到后覆盖新图。字体/显示密度变化只失效受影响数字画布。
- 后续可按同样原则检查地形信息、操作栏及酒馆勋章/徽章，但本项首先交付顶部资源状态栏，不把所有动态界面冻结，也不顺带改战斗规则、数值或动画节奏。

## 验收清单

| 场景 | 必须看到的结果 |
| --- | --- |
| 同一及不同部队连续点击、空地选择、拖图、缩放 | 三个图标节点引用始终不变、src 无重复赋值；资源不变时数字节点引用不变、生成/重绘计数不增加 |
| busy 开关、相同状态重复刷新、世界 revision 变化但资源不变 | 资源栏无新增/移除节点，无相同数值画布重建；操作按钮仍正常响应 |
| 只改变一种资源、同时改变多种资源 | 只更新发生变化的数字区域，图标和未变化数字保持原节点；显示与后端一致 |
| 升级/募兵/工事/训练/运输/解散及失败、取消 | 仅成功提交且值确实变化时更新；无预扣、重复扣除或错误回滚显示 |
| 非白名单路径：回合收入、剧本事件、Mod/扩展资源变更 | 不新增动作名分支也能显示正确数值；这是“不写死”的核心验收 |
| 读档、重开、切局、势力切换、快进、恢复前台 | 不显示旧局/旧势力数据，不为无变化的普通恢复重建整栏 |
| Mod 覆盖三个图标，切回原版，再更新同名 Mod 图片 | 正确使用对应图片，无旧缓存串用、异步旧结果回写或先空白后显示 |
| 数值位数变化、必要字体/缩放变化、横屏安全区及模态遮挡 | 数字不裁切，图标不闪；状态栏层级、触控与设备避让正确 |
| 报告闪烁的实际手机，同 APK/同局修复前后录屏 | 分别核查顶部图标、数字、地图和全屏；记录版本、机型、Android/WebView、高清设置及帧时间，不能用桌面通过替代真机验收 |

建议用节点引用、MutationObserver、文字生成/重绘计数与资源加载记录验证“没有重复创建”，并结合画面观察；仅看请求数为零不能证明没有 DOM 重建。性能数据只报告实测范围。若 HUD 复用通过而整屏仍闪，应保留问题并继续检查视口尺寸、窗口 Insets、画布上下文异常及 WebView 合成，不宣布全部解决。
