# 势力总部队容量

通过 `rewrite/army-capacity.json` 配置玩家和 AI 共用的总部队上限，无需在 `rewrite/extension.json` 注册。内置文件位置为 `rewrite/data/rewrite/army-capacity.json`；Mod 资源目录或 `.ew4mod` 中使用 `rewrite/army-capacity.json`。

上限 = 势力基础额度 + 当前持有建筑的容量总和。若场景另有固定 `UnitsPerFaction`，取两者较小值。陆军、海军、要塞每支均占 1，运输改装不增加数量；这是势力全部单位的上限，不是建筑驻军或单座建筑的招募名额。

## 默认配置

```json
{
  "schema": 1,
  "baseCapacity": 8,
  "factionBases": {},
  "buildings": {
    "city": [0, 2, 3, 4, 5, 6, 7, 8],
    "industry": [0, 1, 2, 3, 4],
    "stable": [0, 1, 2, 3],
    "port": [0, 0, 0, 0, 0],
    "farmland": [0, 0, 0, 0, 0]
  }
}
```

数组下标就是建筑实际等级：`city[3] = 4` 表示 3 级城市总共贡献 4 个名额，不是把 1–3 级相加。第 0 项必须为 0。数值必须是非负整数，字符串、小数、重复字段、未知字段和错误 schema 会被拒绝。

文件不存在时使用默认值。允许省略整个 `buildings` 字段以继承默认表；显式提供 `buildings` 时将替换整张表，未列出的建筑类型贡献 0。已列出的类型必须覆盖其全部可能等级，超出数组范围会明确报 `army.capacity_level`，不猜测下一级容量。自定义建筑可增加同名数组。

## 势力差异化

```json
{
  "schema": 1,
  "baseCapacity": 8,
  "factionBases": {
    "*": {
      "fra": 10
    },
    "conquest1": {
      "fra": 12
    }
  }
}
```

`*` 表示所有剧本，`conquest1` 表示指定剧本。内部键可以是国家 ID（如 `fra`）或完整势力 ID。优先级：指定剧本覆盖全局配置；同一范围内完整势力 ID 覆盖国家 ID；都未命中时用 `baseCapacity`。该值替代默认基础额度，之后再加建筑贡献，不是最终总上限。场景中后续创建的势力可使用其精确势力 ID；有已知国家/模板的剧情势力也会解析相应国家覆盖。

## 生效与存档

Web 修改内置配置后重启服务并载入存档；Android 需将配置随应用/Mod 资源打包后重新启动。切换或重新导入 Mod 会重新读取其配置。单纯刷新正在运行的网页不会让服务进程重新读文件。

当前规则会写入世界存档。旧档载入时补入当前配置；修改配置后载入现有存档，也会采用当前安装配置并清空旧移动撤回历史，防止跨规则撤回。容量文件作为可调政策不改变原版/Mod 的账户存档目录或原内容绑定，但仍参与资源缓存、Mod 文件完整性和实际内容校验。修改存档中政策后再载入，客户端仍以安装配置为准。

占城、失城、建筑升级/降级和单位增减后立即根据当前状态计算。达到或超过容量仍可常规招募；仅当部队数严格大于容量时，三种回合资源总产出（含势力加成）减半、向下取整，需供养部队的总粮食消耗翻倍。后勤免耗粮规则保留。回到容量以内立即恢复正常。顶部超限时部队图标和当前数/上限均变红，沙漏及回合数保持原色。主动召唤仍需剩余容量；训练、任命将领、建筑升级不新增部队，不受新增单位检查限制。

粮食、资源、地点、兵种/军衔和回合次数限制仍然有效。AI 陆军、海军、要塞招募最多填满容量，不主动超限；同时遵守粮食供养条件。失城、剧情援军或接管导致 AI 被动超限时，使用与玩家相同的减产、耗粮及缺粮士气结算，不豁免惩罚。

征服模式 AI 仅在仍超限、缺粮等级至少 2 且已有部队负士气时，尝试应急解散。每国每回合最多 1 支（读档不重置），至少保留 8 支，当回合停止招募回补。候选必须位于本国无建筑、无目标的后方格，距离最近敌军和敌方领土至少 6 格；优先最远、其次低血量和高耗粮。将领、目标部队、要塞、建筑驻军、待命守备、已行动、建造中、后勤或零耗粮部队均排除，无候选则继续正常作战。战役等非征服模式禁用。退款复用玩家算法：各项招募费用 × 当前血量 / 最大血量 × 50%，逐项向下取整。通过现有 `TurnUses` 保存每回合次数，不新增存档版本。

## 客户端字段

- `/api/state` 等世界视图的 `factions[]` 提供 `unitCount` 和 `unitLimit`，顶部显示当前玩家/本地多人操控国的 `unitCount/unitLimit`。
- 地块视图的 `tileInfo.armyCapacity` 是当前等级建筑的单座容量。
- 玩家常规招募不再因动态容量返回 `recruit.capacity`；AI 生产执行仍用此错误阻止主动超限。独立核心场景配置的 `Limits.UnitsPerFaction` 仍为世界有效性硬边界。
