# 空中与地表分层接口

2026-11-02 新增源码接口，需要包含本接口的新构建，现有 0.2.30 发行包不支持。
API 3，电脑 Web 和 Android 共用核心、加载与存档实现。R 本体默认关闭，没有新增航空兵种、航空菜单或设置开关。
仅 Mod 在扩展清单声明配置文件且设置 `enabled:true` 后启用；缺省、无清单、`enabled:false` 均保持原有整格容量、移动和攻击行为。

## 配置

在包根 `rewrite/extension.json` 合并字段，保留其他已用的扩展入口：

```json
{
  "schema": 1,
  "apiVersion": 3,
  "unitLayers": "rewrite/unit-layers.json"
}
```

配置文件示意如下，profile ID 必须是最终运行目录中的完整 ID，不能填写招募卡 ID 或仅兵种名称：

```json
{
  "enabled": true,
  "surfaceCapacity": 1,
  "airCapacity": 1,
  "profiles": {
    "ew4.unit.fra.light_infantry.0": {
      "layer": "air",
      "attackLayers": ["air"],
      "counterattackLayers": ["air"]
    }
  }
}
```

| 字段 | 缺省 | 含义 |
| --- | --- | --- |
| `enabled` | `false` | 显式启用分层机制 |
| `surfaceCapacity` | `1` | 地表层每格容量，整数 1 至 32 |
| `airCapacity` | `1` | 空层每格容量，整数 1 至 32 |
| `profiles` | `{}` | 按完整 profile ID 配置，不同国家、级别须分别列出 |
| `layer` | `surface` | 仅支持 `surface`、`air` |
| `occupies` | 仅 `layer` | 可选占用层数组；非空、不重复、必须包含主层，可为 `["air","surface"]` |
| `attackLayers` | `["surface"]` | 主动普通攻击允许的目标层；`[]` 禁止普通主动攻击 |
| `counterattackLayers` | 沿用 `attackLayers` | 反击允许的目标层；`[]` 禁止反击 |

未列出的 profile 为地表单位，只能主动攻击及反击地表。地表防空单位可保留 `layer:"surface"` 并将目标层配置为 `["surface","air"]`。启用时拒绝未知 profile；配置拒绝未知字段、未知层名、重复层、无效容量及 API 1/2 清单。

## 规则

profile 可选 `targetCategories` 进一步限定旧兵种类别（`infantry/cavalry/artillery/naval/fort`）；缺省不限，空列表禁止普通攻击。它与目标层取交集，并同样约束反击与普通溅射。例如轰炸机配置 `attackLayers:["surface"]` 及不含 `naval` 的类别列表，可阻止攻击舰艇。此配置随战局保存。

- 地表层容纳陆军或海军，仍受原有海陆通行限制；空层可与任何一方地表单位同格，同层仍禁止敌对阵营混驻。默认容量为地表 1 支加空中 1 支，分别保留 ID、生命、行动与将领状态。
- 飞机仅能经过地图有效格，可飞越海、河流、山地和禁行海洋；不能进入无效格，也不会自动赋予舰艇江河通航能力。同层敌军阻挡寻路，其他层不阻挡。招募、事件增兵、技能召唤/传送及撤回按各自层检查容量。
- 飞机移动不占领或扩张领土，不阻止地表占领，不参与地面包围。它不继承脚下建筑、工事、地形防御、建筑治疗或地表环境伤害，不提供或接受原有地面邻格将领光环；自身燃烧、补给、个人技能及总军队数量限制仍适用。
- 普通攻击先按目标层过滤，再检查射程及行动条件；反击另查防守方的反击层和原有反击规则。允许跨层同格攻击时，还需在兵种数值中设置 `minimumRange:0`。溅射只选择与主目标同层、且攻击方可攻击的目标。
- 现有按军队存续的胜负条件仍把飞机算作军队；没有额外的航空基地、燃油或自动返航规则。事件作者应按剧本配置胜负条件。
- 启用后，作战层只在部队属性中显示，底部不增加分层按钮。首次点格优先地表，重复点选同格轮换部队；合法攻击仍优先执行。空军模型与标记稍向右上错开，绘制在地表单位之后。后端选择可用 `op:"select",cell,unit` 指定实例 ID；`targetUnits` 给出实际可攻击的单位 ID，不能仅凭目标格选第一支军队。

## 保存与接口边界

启用规则随战局保存并纳入内容绑定及校验，加载时与当前 Mod 规则匹配；更改层归属、容量或目标层后，应作为新规则版本开新局。不要直接删除旧档的 `unitLayers` 或绕过内容校验。未启用的本体存档不写此可选字段，原有内容指纹保持。

分层独立于旧 `category`。配置空层不会自动新建航空兵种类别、科技分支、将领航空星级或飞机贴图；伤害倍率、旧类别技能和科技仍按原兵种模板计算。Mod 应选合适模板并配套调整数值与素材。

旧 BTL 军队仍从地块归属推导所属势力，没有新增每军所属字段；要在开局形成敌我跨层共格，可通过事件增兵后转属等现有实例接口配置。分层不会自行改写旧 BTL。

AI 的普通攻击、战术移动和战略落点遵守层及目标限制，航空战术权重仍沿用既有模板；没有自动使用运输机投送等新主动技能的专用 AI。
已有范围技能的 `scope:"area"` 仍按原规则选择范围单位，普通攻击的 `attackLayers` 不会自动限制 Lua/技能效果。
本接口没有实现终身一次投送、近支专用光环、侦察情报差、对建筑专用加伤或新航空能力值。这些需要各自扩展及验证。

最小配置源码见[示例](../../examples/unit-layers/README.md)，其旧步兵素材仅用于接口演示。

## 双层单实例与攻击动画

新增 `occupies:["air","surface"]` 表示一个单位同时预留两层容量；实例、生命、行动、经验与将领均只有一份，军队数量计一支，点击一次即选中。招募、召唤、移动、传送、撤回必须两层同时有空位；任意重叠占用层的敌军阻挡路径。攻击和反击可选目标占用层的交集，不增加免费攻击次数。

直升机协同队建议 `layer:"air"`、`occupies:["air","surface"]`、`attackLayers:["air","surface"]`。主层 air 决定飞行通行、无运输船、不占地和不接受原地表加成；两层占位仍保持。水上隐藏地面部分、保留双层占位，地面攻击通道对其无效，它也不能从水上用地面部分攻击；空中通道正常。此规则不是下放/回收地面队的两实体运输机制。

完整 `client/unit-visuals.json` 可新增 `composites`，按完整 profile ID 配置最多8个部件：`{"visual":"动作定义键","layer":"surface","x":-10,"y":24}`。同一单位的部件共享移动及状态，地表部件水上隐藏；一次攻击只播放与后端 `attackLayer`/`counterLayer` 匹配的首个部件，其余保持待机。普通单位仍使用原单一动作库。作战层仅在部队属性显示，不新增底部按钮。

单个动作定义可选 `attackVisuals:{"air":"动作定义A","surface":"动作定义B"}`，按实际攻击通道切换整套 attack/reload/finish 与特效时序；反击同样适用。部件坐标由 composites 定义，视觉不会多结算伤害。需要全套动作和预加载库，非法绑定或坐标会在 Mod 校验时拒绝。

双层/机场最小源码见[扩展示例](../../examples/advanced-units/README.md)，建造与工兵权限见[自定义建筑接口](CUSTOM_CONSTRUCTION.md)。既有五航空目标域和专用技能的缺口仍按上文说明。
