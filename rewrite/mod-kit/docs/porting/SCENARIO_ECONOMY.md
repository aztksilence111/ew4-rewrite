# 剧本粮食与收入接口

需要含本接口的 R 客户端。Android 与 Windows Web 共用规则，未配置时保持原版收入、升级、AI 和缺粮行为。

## 按剧本调整建筑产出

API 3 的 `rewrite/extension.json` 增加 `"economy":"rewrite/economy.json"`。配置格式：

```json
{
  "schema": 1,
  "scenarios": {
    "conquest7": [
      {"kind":"farmland","level":1,"income":{"food":12}},
      {"kind":"farmland","level":2,"income":{"food":24}},
      {"kind":"farmland","level":3,"income":{"food":48}},
      {"kind":"city","level":1,"income":{"food":2}}
    ]
  }
}
```

等级从 1 开始，必须是已有建筑等级；同一剧本不得重复指定同种同级建筑。只替换提供的资源字段；未提供的税收、工业、治疗、扩地保持原规则。建筑升级自动使用新等级对应产出。配置仅对列出的剧本生效，不支持 `*`，不改动基础 `legacy/buildings.json`。后者仍可用于确实需要整个 Mod 都改变建筑定义的情况。

## 事件设置势力与地点收入

在现有 `scenarioEvents` 文件的事件 `effects` 中使用：

```json
[
  {"type":"faction_income","faction":"@player","income":{"food":8}},
  {"type":"site_income","cells":[16810],"income":{"food":24}},
  {"type":"site_income_default","cells":[16810]}
]
```

- `faction_income` 设置每回合势力加成的指定字段，区别于 `food` 的一次性赠粮和 `set_food` 的库存设置；反复设置不累加。
- `site_income` 只针对现有建筑，按地点覆盖指定字段，其他字段保持；示例第三条演示清除覆盖，实际使用时按需要分属不同事件。
- 地点收入随实际控制者转移，不是不可占领的势力保底。覆盖记住设置时的建筑类型；类型改变后不作用于新类型，同类型升级保留地点覆盖的字段。`site_income_default` 清除全部地点覆盖，恢复剧本建筑规则及原有首都加成。
- `faction_create` 可增加 `"income":{"food":4}`，明确新势力的基础收入。省份独立事件应显式赋值，避免照抄模板势力的保底。未指定时维持已有模板继承行为。
- `income` 至少提供 `money`、`industry`、`food` 之一，所有指定值必须是非负整数；负数、空补丁、空地点列表、重复地点及非建筑目标拒绝。不要用这些接口修改库存。

收入顺序为建筑基础、原有地点加成、事件地点覆盖、驻点将领加成、势力基础收入、超军队上限减半。粮食不受势力金钱/工业倍率影响。AI 与玩家使用同一结算与招募预算。仍保留首回合不收支、后续收入后扣军粮、库存不足时的缺粮档位与士气规则；本接口不引入道路运输或围城自动断粮。

启用收入扩展后，点击资源栏粮食可看本人基础、城镇、农田、减产、军队消耗和净收入；地点信息显示实际粮产。不会额外公开敌方收支。

事件修改随战局存档保存，读档不重放一次性设置。建筑规则来自 Mod 内容；修改规则会改变内容指纹，旧战局留在旧逻辑存档空间，新平衡须新开局。基础原版存档不增加空的地点覆盖字段。

[最小源码示例](../../examples/scenario-economy/README.md)；实际参数与守军维护成本应分开平衡，不宜给足以维持整个军队的不可夺取基础收入。
