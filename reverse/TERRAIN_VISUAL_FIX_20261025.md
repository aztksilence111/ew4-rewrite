# 地形清晰度回归修复

日期：2026-10-25。承接用户关于灰蒙地图、河流和陆地边缘锯齿的反馈。优化面向通用大地图及更多兵模，东亚仅为规模参照。

## 根因与最终方案

先前交互时使用的简化占位只绘制陆海底色和领土，缺少完整地图美术与岸线；交互、移动动画和空闲补齐的延迟使其长时间可见。随后试验的低分辨率全图虽然补全内容，却在放大时导致河流和海岸线锯齿。两种方案均已撤回，不应使用它们的画面或计时作为最终交付结论。

当前 Pixi 路径直接使用原始分辨率图片，将完整地形绘制顺序和绘图对象缓存在 GPU 容器中。镜头移动时变换容器，避免反复在 CPU 上合成大块地图并上传；缩近时保留已覆盖区域，减少反复重建。重复背景使用原图平铺，地图图片在进图时预解码，岸线模板分时预热。缓存会跟随地图、图片和文字版本刷新，Canvas 回退保留完整地形。

空间索引、兵模按视野及动作加载、绘图对象复用继续保留。交互和部队移动均不切换低清地形；新城市名称仍可异步补齐。不是通过降低河流或海岸线分辨率换取流畅度。

这证明先前绘制路径存在 CPU 合成及 GPU 提交负担，不能据此认定手机缩放卡顿只由地块显示引起。真机 GPU 帧时间、纹理内存及后续兵模素材仍需测量。

## 通用规模压力测试

`scaling/results.json` 使用原完整地图块实现作基准，生产预热后 ABBA 对照，规模为5372/21488/85952格和252/1008/4032部队。每组包含60个拖动和20个部队移动样本。

最大规模结果，单位ms：

| 视口 | 拖动中位数：原→新 | 移动中位数：原→新 | 冷缩放最大：原→新 |
| --- | --- | --- | --- |
| 桌面 | 2.4→4.4 | 2.4→4.8 | 122.0→9.7 |
| 窄横屏 | 2.3→4.2 | 2.2→4.4 | 173.2→10.3 |
| 竖屏 | 3.4→4.8 | 3.1→4.3 | 264.6→79.4 |

冷缩放长帧减少，稳态提交略贵，竖屏极端仍有79.4ms长帧，不能宣称完全不卡。该重复地图夹具也不能替代未来地图原始素材和兵模的真机测试。旧报告中的123至328→11至15ms使用了视觉不完整的占位方案，已被本结果取代。

当前四组可见纹理记账约6990万至7790万像素；按RGBA粗估仅基础像素就约267至297MiB，尚不含驱动、mipmap、CPU解码及其他内存。不能把CPU地形块像素0解释为GPU内存为0；原图缓存的真机内存风险尚未验收。
