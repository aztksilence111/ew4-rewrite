# rewrite 玩家 AI 设定方案

日期：2026-10-26。状态：已实施并完成源码验证；未生成 APK 或正式发布。实现和验收见 [记录](PLAYER_AI_SETTINGS_20261026.md)，呈现接口见 [AI_CONTROL.md](mod-kit/docs/porting/AI_CONTROL.md)。下文保留原规划背景；建议项以实现记录为准。

## 1. 功能范围

在玩家回合暂停界面增加右侧「AI设定」栏，对指定的本国单位批量设置战斗方针及行动目标。默认由玩家指挥；必须完成方针、单位、目标三个设置步骤并点击「开始执行」，才启用结束回合之前的自动行动。只设置而未启动，或已点击「停止执行」时，结束回合直接进入正常势力轮转，不先进行玩家单位 AI 指挥。全局自动战斗临时接管其余玩家单位，关闭后恢复其持久设定，也必须遵守该执行开关。

本稿将用户已指定的行为作为要求；未明确的交互及冲突处理写为「建议默认」，供进入实现前调整。

## 2. 已核对的源码事实

| 项目 | 当前实现与接入位置 |
| --- | --- |
| 单位方针 | `Ew4.Core/WorldState.cs` 的 `UnitState.Behavior`；`WorldAi.cs` 默认映射仅有 default、0、1、2、3 |
| 行动候选 | `Ai.cs`、`WorldAiUnits.cs`：待机、战术移动、战略推进、原地攻击；行为3仍能原地攻击 |
| 战略倾向 | `WorldAiStrategy.cs`：0半分随机、1全分、2四分之一底分加随机且战略落点限相邻、3零战略权重 |
| 原版兼容 | `Ew4.Legacy/LegacyArmyRestoration.cs` 明确拒绝原存档 Behavior > 3；不能将4解释成已恢复的原版撤退 |
| 玩家结束回合 | `Ew4.Client/ClientGame.cs` 的 end 直接调用 `WorldTurns.EndTurn`，没有玩家单位托管阶段 |
| 现有自动调度 | `ClientGame.AiBatch.cs`、前端 `app.js` 都会在遇到 Human 势力时停止；没有玩家全局自动战斗入口 |
| 行动状态 | `WorldActions.Move` 扣移动力而不设置 `Acted`；仅检查 `!Acted` 会错误接管玩家已移动的单位 |
| 暂停与中断 | `app.js` 具有暂停后停止后续 AI 请求、收齐当前请求后重开/退出的调度边界，应共用 |
| 地图输入 | `app.js` 当前单指拖动平移、双指缩放；框选需要独立模式，不能同时触发原平移/地块菜单 |
| 目标箭头 | `battlefield.js` 已绘制教程地图箭头及阴影；现有颜色按地块归属选择，新目标应显式使用红色 |
| 共用前端 | `Ew4.Web/wwwroot/` 同时供 Web 与 Android 使用；暂停已有左侧目标栏及居中菜单 |

## 3. 暂停右栏与按钮流程

### 3.1 布局

- 暂停时在右侧显示标题「AI设定」及四个主要按钮，顺序为「指定战斗方针」「框选单位」「指定行动目标」「开始执行」。进入执行状态后，第四个按钮原位变为「停止执行」。仅当前拥有操作权的玩家可编辑其本国单位。
- 按钮使用现有底部兵种数据/操作按钮的尺寸基准、文字组件和缩放变量；整列高度由内容决定，不将整列压成一个底部按钮的大小。
- 风格沿用灰色金属面板、原有边框花纹及按键反馈。优先复用已有素材；需要专属贴图时再生成可独立替换的 PNG，文字保持独立绘制。
- 按用户后续要求，方针弹窗及地图选择的确认键统一采用「确认」文字矩形键，不使用圆形对勾；其文字、底图、尺寸与颜色均可通过呈现接口修改。
- 侧栏提供已选单位数、当前方针（批量不一致时显示「混合」）、目标摘要及三个步骤的完成状态。前三个按钮编辑草稿，第四个「开始执行」同时承担原子提交设定和启用执行的作用，不再另设「应用设定」；保留取消草稿入口。
- 桌面布局为左目标栏、中央暂停菜单、右 AI 栏；竖屏或窄横屏不足时，使用 AI 栏展开/收起及内容滚动，避免三个面板重叠。具体布局断点由实际测量决定。
- 非本玩家回合仍可暂停，但该栏为只读/禁用，不默认选中其他玩家或盟军。

### 3.2 建议默认的操作顺序

`暂停 → 框选单位并确认 → 指定方针并确认 → 指定目标并确认 → 开始执行 → 返回战场 → 结束回合时先执行托管`

允许先选方针再框选，草稿在当前暂停编辑流程中保留。进入暂停前已选中一个合法本国单位时，建议预选该单位；否则从空选择开始。预选单位、默认方针或仅打开按钮均不计为完成设置，三个步骤必须分别实际设置并确认。

「开始执行」仅在三个步骤全部确认、至少选中一个合法本国单位且目标有效时可点击；目标可以暂时不可达，但不能未指定。后端必须独立复核完成状态、单位及版本，不能只靠前端禁用按钮。启动成功后一次提交持久命令并进入执行状态，按钮变为「停止执行」。普通托管仍在结束回合时行动，点击开始本身不自动结束玩家回合。

未启动时，无论只设置部分步骤还是全部设置完毕，点击结束回合都不进入玩家托管阶段。「停止执行」关闭后续托管，保留已提交的方针、单位和目标便于调整或再次启动；不撤销已经完成的行动。再次启动仍校验三个步骤及当前配置的有效性，缺项或相关确认因修改而失效时必须补齐。

退出或取消丢弃未提交草稿。方针弹窗确认、框选确认、目标确认只完成对应步骤，不提前启用托管。执行中须先点击「停止执行」再编辑前三项；已发出的行动在提交完成后停止，期间不能重复启动。

### 3.3 指定战斗方针

弹窗顶部固定「玩家指挥」，下面为五种方针按钮，单选；右下角设置确认按钮。初始全部玩家单位均为玩家指挥。混合选择不擅自覆盖已有值，只有用户主动选择的字段才批量修改。主动选择一个方针并确认后，才完成「指定战斗方针」步骤；取消或保留未经确认的默认值不计完成。

| UI 选项 | 建议稳定 ID | 行为定义与实现方式 |
| --- | --- | --- |
| 玩家指挥（默认） | manual | 没有已启用的目标命令或全局自动接管时，结束回合不自动操作，即使仍有移动力/攻击机会 |
| 0 自由行动 | free | 复用行为0：综合比较待机、移动、进攻与战略目标 |
| 1 积极进攻 | aggressive | 复用行为1：不生成普通待机候选，战略推进采用完整权重；仍遵守合法行动限制 |
| 2 消极进攻 | cautious | 复用行为2：允许待机，战略目标权重更保守，战略移动落点限相邻；并非全局移动力强制为1 |
| 3 原地防守 | hold | 复用行为3：不主动移动，可以攻击当前射程内合法敌军 |
| 4 逃离战场 | retreat | 新增 rewrite 方针：择合法安全落点撤离威胁，不删除单位、不退出地图、不自动宣告战败 |

「逃离战场」建议默认依次比较：降低敌军可攻击威胁、避开灾害、靠近己方安全区域；稳定同分规则。无更安全合法落点则待机，不主动攻击；反击沿用战斗规则。海军/运输/陆军各按通行规则判断，不擅自购买运输或消耗资源。需单独实现并验证，不能把4塞入现有映射后冒充完整功能。

建议默认：明确选择「玩家指挥」同时清除此批单位的行动目标，回到完整手动状态，并使目标步骤变为未完成；如随后重新指定目标，可完成三步后启动纯目标移动。单独「清除目标」只移除目标，保留已有战斗方针，也使目标步骤变为未完成。

### 3.4 框选单位

- 进入地图专用选择模式；收起暂停面板，停止自动调度，隐藏原侧边按钮和底部操作区，包含暂停、地图模式、蜂窝/网格、沙漏、撤回、寻找单位与快进等。
- 点击任意地块均不调用普通 `selectCell`，不弹出底栏，不移动、不攻击。
- 单指/鼠标拖动显示矩形，以单位所在格中心是否落在矩形内判断；只选择当前可编辑的本国单位。点击单位切换该单位选中状态。
- 建议默认多次框选为累加选择；点击已选单位取消单个选择。右下角的大确认按钮旁放置「取消选择」，取消恢复进入本次框选前的选择并返回右栏。
- 确认非空合法单位集合后，完成「框选单位」步骤并回到暂停右栏；目标及方针设置仍待「开始执行」统一提交。空选择和取消不完成该步骤。
- 框选与地图平移互斥。建议默认桌面使用右键或中键平移，手机使用双指平移/缩放；双指手势取消未完成的矩形，避免误选。地图边缘拖动可触发受限速度自动平移。
- 矩形及选中轮廓随镜头正确变换。处理 pointercancel、失焦、旋转及指针捕获释放，不保留悬空选区。

### 3.5 指定行动目标

- 已有单位选择后进入目标地图模式；隐藏规则与框选一致。可点击地图任意有效格，允许敌军格、海格及不可通行格作为意图目标。
- 选中后使用教程同款红色箭头/阴影，在目标格与选中单位之间绘制高亮虚线；不向教程 Runner 发送事件，不借用或覆盖教程等待状态。
- 右下角「确认」保存草稿目标、完成「指定行动目标」步骤并返回右栏，旁边「取消」恢复进入前的目标且不完成步骤。再次点击地图更换预览目标。
- 允许选择不等于保证能抵达：寻路仍尊重兵种、运输、地形、阻挡及占用规则。不可达时保留目标及受阻状态，不反复抛错或卡住结束回合。
- 建议默认目标跨回合保留，抵达后清除目标；持久战斗方针保持，原玩家指挥单位恢复纯手动。提供独立「清除目标」命令。
- 三步骤完整性是点击「开始执行」时的门槛；执行中正常抵达而清除目标，不反向撤销已开始的其他方针行动。停止后再次启动若已无目标，则需重新指定并确认目标。
- 虚线表示命令关联，不宣称为实际可行路线。编辑时显示全部已选单位的线；普通地图建议仅显示当前选中单位/批次的线，避免全军连线遮挡地图。

## 4. 单位状态与规则优先级

### 4.1 持久设定与有效控制

建议在世界/会话存档模型中增加独立玩家命令记录，不直接覆盖原 `Behavior / RestoreBehavior / BehaviorExpiry`。原字段被剧情及生命周期恢复使用，复用会导致玩家设置被刷新或全局自动模式退出覆盖剧情状态。

每单位至少记录：`ControlPolicy`（默认 manual）、`GoalCell`（可空）、本势力回合的玩家操作标记/回合令牌。按玩家席位记录 `ExecutionEnabled`（默认 false）、`AutoBattleEnabled` 及结束回合托管阶段/进度；编辑草稿另记方针、单位、目标三个步骤的确认状态，并绑定对应配置，禁止旧确认误用于已失效的新配置。具体 record 与存档字段位置由实现时结合现有序列化规范确定。

有效控制计算前先检查执行开关：`ExecutionEnabled == false` 时，已配置方针、目标及全局自动战斗选项都不触发玩家单位自动行动，也不产生自动回合推进。开关只能通过三步校验成功后的「开始执行」启用，读档缺少该字段时默认关闭。

执行已启用时，有效控制计算：

1. 存在明确目标：优先处理目标命令。
2. 存在显式托管方针：按该方针生成行动。
3. 全局自动战斗开启且持久方针为 manual：临时使用自由行动。
4. 其他情况：保持玩家指挥，不进入自动行动队列。

建议默认目标优先于原地防守/撤退等方针；UI 中同时展示「目标优先」，避免玩家误解。清除或完成目标后继续原持久方针。

目标命令优先降低实际寻路剩余代价，允许绕障。纯目标/manual 单位只执行移动，不擅自攻击、买船或使用道具；遇敌军占格则停在可达接近点并保留目标。已有托管方针的单位可选择符合目标推进的合法攻击，不转去追逐无关敌军。该冲突处理属于建议默认。

### 4.2 「本回合未行动」的判定

- 不修改 `Acted` 的现有战斗意义，避免影响移动后攻击、恢复与回合结算。
- 在成功提交的玩家主动命令处记录操作标记：移动、攻击、主动技能、训练、施工、购买运输、单位道具等按实际受影响单位登记；失败、查看、框选、设置 AI 方针不登记。
- 建议默认玩家移动过的单位即跳过本次结束回合托管，即使还能攻击。新招募/部署当回合已不可行动的单位也不能因设定托管获得额外行动。
- 反击、被动受伤、剧情位移不作为玩家主动操作；仍检查存活、眩晕、施工和当前实际行动预算。
- 撤回移动需同步恢复对应玩家操作记录，保留此前其他主动操作标记；不能把撤回前后的移动力差当作唯一证据。
- 回合令牌含势力及该势力回合序号，支持本地多人；进入该势力下一回合时刷新，不靠任意 Revision 变化重置。
- 旧存档缺少历史操作记录时，建议保守跳过载入当回合全部玩家单位的结束回合自动补行动，下一个本国回合正常启用；避免旧档已移动但仍有余额的单位被重复接管。

### 4.3 AI 标记

执行启用后，显式托管、仅有目标或正被全局自动战斗临时接管的单位显示「AI」。未开始、只有草稿或已停止执行的单位不显示 AI 标记，目标预览仍可在编辑时查看。已手动操作本回合但仍处于执行状态的单位继续显示，标志代表已启用托管，不代表本回合必定执行。

标记使用独立绘制层与可替换素材/字号/锚点，避开血条、将领头像及现有阵营字母；在远景和移动动画中制定可读性规则。普通玩家指挥且无目标时不显示。

## 5. 结束回合与全局自动战斗

### 5.1 结束回合按执行开关分流

未开始或已停止：`点击结束回合 → 原 EndTurn → 其他国家 AI → 下个玩家回合`。

已开始执行：`点击结束回合 → 建立本国托管队列 → 逐步执行合法行动 → 队列完成 → 原 EndTurn → 其他国家 AI → 下个玩家回合`。

- 后端负责队列资格和阶段，前端负责展示及调度；不能仅在 JS 点击事件循环一遍单位，否则读档和 Android/其他入口可能绕过规则。
- 结束回合入口及托管单步/批处理入口均复核 `ExecutionEnabled`；设置过方针、目标或自动战斗开关不能隐式启用执行。
- 开始时按稳定顺序选出有效托管且本回合未经玩家操作的单位。只执行单位命令，不调用包含招募、建造、派遣的整个 `WorldAi.PlanStep`。
- 单位进入自动执行后可完成一次合法的完整行动序列，例如移动后攻击；不得因自动移动自身产生了状态变化而提前跳过后续合法动作，也不得刷新预算。
- 每次提交重新校验 Revision、存活、归属、目标及可用行动；自动行动过程不并发执行单位命令。
- 对未推进状态的计划、不可达目标和无候选单位标记本次完成/受阻；设置步数预算，保证最终能够结束回合。
- 沿用现有动画、战斗对白、胜负与当前国灭亡恢复入口；对话/选择先等待，胜负先终止，再决定是否继续队列，不重复回合末结算。
- 托管中可暂停，暂停只允许当前提交完成、停止后续请求；返回战场继续原队列。暂停本身不取消本次结束回合请求。保存、读档、退出/重开遵守当前请求收齐规则，保存阶段与已完成进度，恢复后不重放动作。
- 托管阶段禁用普通单位命令和设置修改；右栏第四个按钮保持「停止执行」，取消尚未执行部分、关闭执行开关，回到当前玩家回合，不自动执行 EndTurn。再次手动点击结束回合时直接进入正常势力轮转。

### 5.2 全局自动战斗

目前没有现成玩家入口。建议在 AI 右栏增加「自动战斗」选项；该选项只配置运行方式，只有三个设置步骤完成并已点击「开始执行」，才按上述玩家托管阶段及原其他国家 AI 循环推进。执行开关关闭时，单独开启自动战斗不行动也不自动过回合。

- 持久 manual 单位有效方针临时变为 free；显式 free/aggressive/cautious/hold/retreat 不变，已有明确目标继续优先执行。
- 使用有效方针覆盖层，不批量改写单位持久设定；关闭后自然还原 manual，不把原先显式自由行动单位错误恢复成手动。
- 本回合已由玩家主动操作的单位仍不追加自动行动，下一回合再按有效方针接管。
- 自动模式中新招募或新获得的玩家单位初始持久状态仍为 manual，满足行动条件后才临时接管。
- 关闭自动战斗时停止连续回合推进和临时自由行动，等当前提交完成后停留在合法阶段；显式命令仍受「开始/停止执行」开关控制。点击「停止执行」则同时停止所有玩家单位托管及全局自动推进，恢复临时接管的 manual 单位；已经结束的回合不倒回。与临时暂停区分，暂停不自动关闭执行开关。
- 建议默认只自动执行单位行动和回合推进，不自行招募、花资源、派将、使用道具；剧情选择等待玩家处理。若以后扩展经济托管，应独立设置。
- 本地多人建议只接管开启该开关的当前玩家席位，到其他人类席位停下，不擅自控制其他玩家；需与现有玩家轮换入口一起验收。

## 6. 修改接口与模块拆分

沿用现有 Mod 覆盖、扩展加载和呈现配置方式，不另建平行资源系统。建议增加独立的 `rewrite/ai-control.json` 呈现配置，最终名称在实现时与扩展目录约定统一。

呈现接口预留：右栏/按钮背景与按下态、标题和按钮文案、多语言标签、顺序及尺寸/间距/缩放、确认/取消尺寸与锚点、AI 标记图与位置、目标箭头图、虚线颜色/宽度/节距。资源路径须通过既有 Mod 路径校验，缺项回退内置值，非法配置给出明确错误。

逻辑接口使用稳定字符串 ID，不以按钮位置作为协议。前三步建议仅开放已有规则可承载的评分参数及显示配置；新增执行器属于显式注册扩展，未知 ID 拒绝，不静默回落。完成时按 API 兼容政策判断是否升级 Mod API/存档版本。

| 层级 | 建议修改范围 |
| --- | --- |
| Core | 玩家命令与校验、有效策略解析、目标路径候选、撤退候选、结束回合托管队列与进度 |
| Client | 批量设置/清除命令、玩家操作记录、状态投影、存读档迁移、单步/批处理及权限 |
| Legacy/Mods | 新呈现配置的加载、默认值、验证、资源覆盖与说明；不扩大原版 Behavior 编码 |
| 共用前端 | 独立 `ai-control.js/css` 管右栏及草稿，独立地图交互状态管框选/选目标；接入现有 app 状态和暂停调度 |
| Battlefield | 选择矩形/轮廓、AI 标记、目标箭头与虚线；Canvas/Pixi 两种路径保持一致 |
| Verify/ClientChecks | 规则、存档、回合调度、多人及中断恢复检查；浏览器工具验证实际交互 |

建议接口分为读取设定、确认三个设置步骤、开始执行（原子应用并启用）、停止执行、清除目标、切换自动战斗、开始结束回合托管及托管单步/批处理。统一走当前 ClientCommand/RPC 约定，携带当前版本及明确单位 ID；开始执行必须在后端核验三个步骤均完成，设置批次全量校验后一次提交，部分失效时整批拒绝并刷新，不悄悄漏设。

## 7. 实施顺序与验收

1. 数据及回合规则：新增持久命令、三步骤确认及执行开关、操作记录、存档兼容、稳定调度；先证明未启动时即使已配完方针和目标，结束回合也不会自动操作玩家单位。
2. 完成六选项：复用0-3、实现撤退及目标路径；明确目标冲突、抵达与受阻行为。
3. 共用界面：暂停右栏四按钮、三步完成门槛、「开始执行/停止执行」切换、方针弹窗、框选与目标模式、大确认/取消按钮；先用原资源组成可用界面。
4. 地图表现与接口：AI 标记、固定红箭头、高亮虚线、素材/尺寸配置和最小 Mod 源码示例。
5. 全局自动战斗与恢复：临时自由行动、关闭恢复、暂停/停止、剧情及灭亡流程、普通和批处理一致。
6. 桌面/手机横竖屏及 Canvas/Pixi 验收，再按用户后续要求决定是否构建发行包；完成测试后依仓库规则清理全部临时产物。

关键验收场景：

- 开局/新招募均为玩家指挥；无设定结束回合绝不自动操作。
- 三步骤未全完成时开始执行禁用；仅打开/取消弹窗、默认方针、预选单位、空选择均不冒充完成。后端拒绝绕过校验的启动请求。
- 三步骤全部确认但未点击开始执行，或已停止执行时，过回合直接轮转，不发生玩家 AI 行动；仅开启全局自动战斗选项也不能绕过此门槛。
- 开始后按钮变停止、AI 标记出现；停止后按钮恢复开始、标记移除且设置保留，等待当前提交后不再发出新行动或自动结束回合。
- 五种方针各有可观察的正确行为；原地防守不移动但可攻击，撤退不自删或冲向更高威胁。
- 玩家移动过但 `Acted == false`、攻击过、撤回过、刚招募和失败命令等边界符合操作记录规则。
- 单位能在正常预算内移动后攻击；暂停/读档续接不重复移动、攻击、结算或消耗随机数。
- 框选/点选仅选本国，矩形与镜头一致；原按钮和底栏全部隐藏，空格点击无误触，取消恢复进入前状态。
- 任意有效格可设目标；海陆不通、敌军占位、同格抵达、跨回合绕障、目标消失/失活及清除目标均不挂起回合。
- 手动+目标、显式托管、全局临时接管组合均显示正确 AI 标记；关闭全局模式精确恢复持久方针。
- 自动模式只控制授权玩家席位；事件对白、胜负、反击灭亡当前国、单位死亡/转属后流程正常。
- 普通/批处理在相同初态下最终世界、存档、战斗与 AI 随机状态一致。
- 桌面、窄横屏、手机竖屏及带安全区布局无面板重叠、文字裁切或按钮漂移；Mod 替换素材及缺项回退正常。
