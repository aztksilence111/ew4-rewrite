# 任务、成就及局外奖励接口

共享 Web / Android 客户端。R 版默认没有条目；指挥部使用原版蓝色按钮与通用详情窗，任务和成就入口位于筛选右侧。筛选向右展开，主按钮始终显示“筛选”。展开时覆盖右侧入口，点击外部一次仅关闭菜单。

## 接入

在 `rewrite/extension.json` 中使用 API 2 或 3，将 `metagame` 指向规则文件；已有该字段时直接向原规则文件增加 `objectives`，保留其他配置。文件参与扩展摘要与 Mod 导入校验，不允许路径越界、重复 JSON 键、未知字段或未知条件类型。

```json
{
  "schema": 1,
  "apiVersion": 2,
  "metagame": "rewrite/metagame.json",
  "presentation": "rewrite/presentation.json"
}
```

规则文件以下仅为格式示例，不是 R 版内置任务：

```json
{
  "schema": 1,
  "objectives": [
    {
      "id": "author.conquest-victory",
      "kind": "achievement",
      "name": "成就名称或字符串表键",
      "description": "作者填写目标和奖励说明",
      "mode": 2,
      "scenario": "conquest1",
      "country": "fra",
      "conditions": [
        { "type": "battleWon" },
        { "type": "citiesControlled", "count": 10 },
        { "type": "unitsDestroyed", "count": 20 },
        { "type": "roundAtMost", "count": 50 }
      ],
      "reward": {
        "medals": 100,
        "badges": 2,
        "items": { "ew4.item.0": 3 },
        "commanders": ["ew4.commander.1"]
      }
    }
  ]
}
```

`kind` 为 `task` 或 `achievement`。二者使用相同条件及一次性领奖机制，分别显示在任务、成就列表。`id` 是稳定身份：1–96 个 ASCII 字母、数字、点、下划线或横线；不要在发行后为新奖励复用旧 ID，也不要用改 ID 的方式重置同一奖励。每套内容最多 256 项，每项 1–32 个条件。

成就可设置 `"hidden": true`（默认 false，仅用于 achievement）。未完成时服务端列表不返回该条目及其名称、说明、条件；达成后自动显示并可领取，领取后仍显示为“已领取”，重启、失去原持有条件或重新打开列表不会隐藏。任务与成就面板均有可见纵向滚动条，支持拖动、滚轮、触摸和列表聚焦后的键盘滚动。

`conditions` 默认全部满足（AND）；设置条目级 `any: true` 改为任一满足（OR），暂不支持嵌套分组。`mode` 可选：1 战役、2 征服；`scenario` 和 `country` 可选，必须是已登记剧本 ID 和规范国家 ID，例如 `fra`。引用项、指定地点范围、剧本与模式不一致会在内容加载时拒绝。

## 条件

所有 `count` 默认 1，必须是正整数。局外条件检查当前账户；局内条件检查操作国，不把盟友战果合并进来。

| type | 含义与字段 |
| --- | --- |
| `commanderOwned` | 当前名册中将领数量；可用 `id` 指定定义 ID，如 `ew4.commander.1`，不是实例 ID。已派遣但仍属账户的将领仍计入。 |
| `itemOwned` | 当前拥有的物品份数，包含已装备副本；可用 `id` 指定装备/物品 ID，如 `ew4.item.0`。未指定时合计所有物品份数。 |
| `campaignUnlocked` | `id` 指定隐藏战役的标准关卡 ID；只检查账户的实际解锁记录，不能以菜单可见或允许进入代替；`count` 固定 1。 |
| `campaignStars` | `id` 指定关卡的历史最高星数，或未指定时累计所有关卡的最高星数。 |
| `cellControlled` | 当前控制 `cell` 指定的地图格索引；必须同时设置条目的 `scenario`，`count` 固定 1。支持城市或其他地点，不按易变的显示名称匹配。 |
| `citiesControlled` | 当前控制的城市格数；含开局自有城市，不包含工厂、马厩、港口、农田。 |
| `citiesCaptured` | 单局实际新取得控制权的不同城市格数，含中立城，不含开局自有城；同局丢失后夺回同城只计一次。 |
| `unitsDestroyed` | 单局操作国战斗系统记录的消灭部队数，含反击和溅射击杀；不把部队消失、调动、友军击杀误作战果。 |
| `battleWon` | 当前战局已完成结算且获胜，`count` 固定 1。 |
| `starsAtLeast` | 当前已结算战局星数至少 `count`，上限 5；与将领星区无关。 |
| `roundAtMost` | 当前回合不超过 `count`。需要“限回合获胜”时必须组合 `battleWon`，单独使用会在开局满足。 |
| `eventTriggered` | `id` 指定战局已触发的剧情事件 ID，可结合作者已有剧情事件实现更复杂条件。 |

`citiesCaptured`、`unitsDestroyed`、`battleWon` 支持条件级 `scope: "lifetime"`，跨战局累计；默认 `"battle"` 为当前单局。跨局数据仍按条目的模式、剧本、国家筛选，其余条件不支持 lifetime。局外将领/装备/解锁条件通常不设剧本限制；若设置，必须在匹配的战局中达成。统计与条件观察仅支持单人战役/征服，不纳入教程、本地多人或他国轮次数据。

条件每次正式状态提交、新开局/读档和打开指挥部/列表时观察；完成后持久保留，即使之后出售装备、失去城市也不撤销。所有 AND 条件须在同一次观察时满足；不同时间分别达到各条件不等于完成。跨局计数从启用接口后开始记录，击杀可从已加载战局现存击杀计数恢复，无法重建旧版本未记录的过去占城过程。新增配置不追溯缺失历史。

## 领奖与保存

- `POST /api/objectives` 接受与现有客户端相同的 `q` JSON 查询参数；`{}` 或 `{ "op": "list" }` 返回 `revision`、余额与 `entries`。
- 条目返回名称、说明、奖励、`completed`、`claimed` 和各条件的 `current` / `required` / `complete`。完成记录与当前进度分开，失去当前条件后完成状态仍可领取。
- 领取参数：`{ "op": "claim", "offer": "稳定条目ID", "revision": 账户当前修订号 }`。客户端不得传入奖励数量或已完成状态；服务端只读取作者配置和账户完成记录。
- `reward.medals` / `reward.badges` 为非负整数，表示局外勋章/徽章，不改局内金钱、工业或粮食。奖励为零也允许作为纯成就记录。
- `reward.items` 为物品定义 ID 到正整数数量的映射，最多 256 种；`reward.commanders` 为将领定义 ID 数组，最多 64 位，不能重复。两者可省略，默认空。奖励 ID 必须存在于作者的物品/将领目录中，未知引用在导入与加载时拒绝。
- 发放物品不需要该物品出现在剧本商店、指挥部货架或商店池；发放将领不需要其 `drawlots` 为 1，也不需要军事学院有该报价。奖励直接进入局外库存/名册，不自动添加商品或修改抽取资格。作者可只在目录中定义奖励专属物品和将领，再通过本接口发放；需要完全不上架时，还须在作者自己的剧本货架与指挥部 `shopSlots` 中排除相应物品。
- 奖励将领使用定义中的初始军衔、爵位、能力、训练和装备；自带装备也增加库存并参加唯一性及数量检查。已拥有同定义将领时拒绝整条领取，不覆盖玩家将领、不重复创建或自动折算货币。物品的唯一性、最大持有量、库存种类容量、名册总容量和星级区容量均适用；无法领取时保留完成状态和待领奖励。多个条目发同一唯一装备或将领时，作者应提前处理条件和替代奖励设计。
- 同一 ID 在同一账户只领取一次。领取时检查修订号、完成状态、回执、容量和数值溢出；货币、库存、名册与回执作为一个账户写入事务保存，失败不部分发奖。奖励将领会从当前学院报价中移除。领取后的活动对局账户同步，读回同局旧存档不会丢失奖励或再次领奖。
- `completedObjectives` 和 `objectiveBattles` 是新增可选账户字段；旧账户缺字段默认空。以既有 `battleId` 与操作势力分别记账，击杀取同局同势力已见最大值，占城取城市格集合，胜局按战局去重。剧情切换扮演国家不会混合两国的记录，同局同城也不因切换势力重复累计。回放同一战局不会重复累计，但正式重新开局是新的战局。

## UI 扩展

需要增删指挥部按钮、重排整个页面或增加子页时，使用[headquartersPresentation完整布局接口](HEADQUARTERS_LAYOUT.md)。以下字段仅调节默认工具栏与任务/成就弹窗，不限制自定义页面的按钮数量。

在已有 `presentation` 文件中可增加以下布局键，省略时使用 R 版原版风格默认值：

```json
{
  "headquarters": { "left": 30, "top": 28, "width": 70, "height": 40, "gap": 5 },
  "tasks": { "width": 420, "height": 240, "gap": 4 },
  "achievements": { "width": 420, "height": 240, "gap": 4 }
}
```

坐标为原游戏菜单逻辑像素。工具栏按钮宽度限制 40–90、高度 28–40、间距 2–8；实际总宽还会按军事学院左侧可用空间等比收窄，保留一行向右展开。面板宽度至少 280、高度至少 140，上限沿用通用布局验证（宽 560、高 300），并由既有弹窗适配器适配设备视口。列表为滚动原生行，姓名/描述与奖励使用原字体及勋章、徽章素材。替换原图集中的蓝/橙通用按钮和字体时，新入口、列表和领奖按钮一并沿用新材质；不接受作者注入任意 HTML 或前端脚本。

验证：`dotnet run --project rewrite/Ew4.Verify -- <root> --objectives-only`；`node tools/verify_hq_objectives.cjs <独立预览URL> <证据目录>`。测试中的配置和模拟条目不写入 R 版正式数据。
