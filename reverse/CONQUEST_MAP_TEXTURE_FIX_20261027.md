# 征服地图消失与纹理生命周期核查

## 结论与边界

`_batchEnabled` 是 Pixi GPU 纹理批处理字段，报错指向绘图阶段。按钮与点选依赖的世界数据仍能工作，与地图整帧绘制失败的现象相符。读档会调用地图绘制，故读档时出现此报错本身不能证明存档内容已经损坏。

确认共享渲染器存在两处纹理生命周期缺陷，并修复源码：

- `release()` 原先立即销毁纹理。Canvas式绘图接口实际先排队Sprite，直到 `end()` 才提交GPU。如果本帧已经排队使用某图片，后续缓存淘汰又释放它，提交时就会读取失效纹理。实际调用路径包括256项血量圆环缓存满后的淘汰；生成新圆环可能释放本帧较早部队已使用的旧圆环。
- 保留地图层原先只检查图片键是否仍在 `sources` 中。图片被释放再重传时，键重新存在，但保留层仍持有上一批已销毁的纹理，错误地继续复用。

初次核查未取得用户故障存档，普通AI设定操作回归也未自然重现用户当次的 `_batchEnabled` 异常。历史发行源码的定向复现分别报 `width`、`uvsFloat32` 空引用，证明纹理生命周期问题，未将这些异常当作完全相同的调用栈。后续原档与真机结果见下节；仍不能将上述缺陷断言为当次故障的唯一原因。
