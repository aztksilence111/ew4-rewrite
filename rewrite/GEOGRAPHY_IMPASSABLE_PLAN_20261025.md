# rewrite 通用禁行地形规划

日期：2026-10-25。状态：用户授权后已实施通用规则、Mod API 3、原版派生素材和当前东亚121格雪山/3条通道。日本仍为参考构图，正式海区划分待制图；下文保留实施前设计依据，实际接口以[作者文档](mod-kit/docs/porting/GEOGRAPHY.md)为准。

实施与验证结果见[交付记录](GEOGRAPHY_IMPASSABLE_IMPLEMENTATION_20261025.md)，下文候选比较及阶段安排为原规划记录。

## 1. 目标和范围

为 rewrite 全局新增两种可供任意地图及 Mod 使用的地块类型：不可通行山地、不可通行海洋。东亚喜马拉雅与日本大图是首批应用，不是这两种规则的适用边界。Mod 作者应能配置位置、引用默认素材、替换外观和复用规则，无须修改 C# 或前端源码。

- **当前东亚地图**：喜马拉雅主要山脊改为禁行雪山，只保留少数贯穿山脊的山口通道。
- **规划中的日本大图**：沿用已确认的顺时针15°、左界收窄50像素构图，直接参照当前图上的大陆架、陆坡与深海区分界勾绘禁航区；海峡和岛链通路做落格连通核对，不按统一离岸距离另画海带。
- 神罗及其他地图未来可直接调用；本轮不安排它们的实际地块修改。

## 2. 已核对的现状

| 入口 | 当前行为与规划影响 |
| --- | --- |
| `Ew4.Core/HexMap.cs` | `MovementCell` 有 Active、Sea、TerrainCost；`Movement.EntryCost` 统一计算通行消耗。普通山地成本6，但步兵和 Geography 技能按基础陆地成本通行；AllowOverdrawnEntry 还允许超额进入。必须增加独立禁行判定，不能仅提高成本。 |
| `data/legacy/terrain-rules.json` | 普通陆地3、丘陵5、山地6、海洋1；这些已有规则不自动升级为禁行。 |
| `Ew4.Legacy/LegacyTerrain.cs` | BIN 地形解析为移动/防御/火焰属性；海洋目前依赖 BackgroundKind==1。不追加旧 BIN 数值编号来冒充新类型。 |
| `tools/eastasia_relief.py` | 现有低、中、高山只是原山地素材的外观分级；高山不等于禁行，不能直接批量转为新地块。 |
| `Ew4.Client/ClientContent.cs` | 实际地图仍由 original BIN 读取。只给 `.map.json` 增加属性不会接入正常开局；需在真实加载链中合并通用地理扩展。 |
| `Ew4.Persistence/MapDocument.cs`、`WorldSave.cs` | 现代地图版本1、世界存档版本4，JSON 拒绝未知成员，存档另有内容指纹。须明确读取兼容与地图改版边界，不能宣称新增属性自然兼容全部旧档。 |
| `Ew4.Mods/ModFiles.cs` | 现有 `rewrite/` 扩展目录允许 JSON、Lua、PNG，可沿用此路径体系；仍须接入实际加载、导入校验和逻辑指纹。 |
| `Ew4.Web/wwwroot/battlefield.js` | 地形精灵显示以 Active 作为可见条件；不能把禁行格简单改成 Active=false，否则会与图外无效格混淆。 |

## 3. 通用规则与内部表示

建议公开类型 ID 为 `impassable_mountain`、`impassable_sea`，归入引擎内置地理类型定义。保留底层山地/海洋属性，并给 `MovementCell` 增加独立禁行原因枚举（暂名 `Barrier`：None、Mountain、Ocean）；不同时存储多个可互相矛盾的禁行开关。

| 地块 | 基础属性 | 移动规则 | 默认外观 |
| --- | --- | --- | --- |
| 普通山地 | 陆地、原山地防御/成本 | 沿用现有兵种与技能规则 | 原山地及既有高度变化 |
| 不可通行山地 | 陆地、山地；Barrier=Mountain | 地面部队禁止进入、穿越、停留 | 原山体轮廓＋峰顶积雪，区别于普通高山 |
| 普通海洋 | Sea=true | 沿用舰船/运输规则 | 原版海面 |
| 不可通行海洋 | Sea=true；Barrier=Ocean | 舰船及运输部队禁止进入、穿越、停留 | 基于原版海面压暗的深色海洋 |

执行顺序：先核验有效格及禁行属性，再计算兵种、技能、河流、桥梁和行动力。额外行动力、Geography 技能、桥梁、运输状态及超额进入均不能解除禁行。

- 保留 Active=true：地块真实存在，可显示、点选并查看“不可通行雪山/禁航远海”。
- 同一判定用于玩家路径、路径提交、AI即时可达、多回合距离场、连通分量、战略目标及移动缓存；禁行格不能作为距离场零距离种子。
- 招募、部署、空降、召唤、传送落点及剧本生成单位也须拒绝禁行格。传送飞越与普通行走分别处理，但落点不得在禁行格。
- 禁止放置城市、设施、港口、工事、胜利目标或初始部队；配置冲突报出地图名、格号和来源，不自动挪动实体。
- 禁行地块不参与扩张占领、辖区传播和可占领目标统计；默认无主且不作为必须攻占的战场目标。
- “禁行”不自动新增炮击视线、弹道或飞行航路阻挡规则；本阶段只约束地面/海面通行及实际落点。
- 初版不加入动态造路、季节融雪或技能解禁，避免改变本轮规则边界。Mod 可直接把某格恢复为普通山地/海洋。

## 4. Mod 配置和作者工作流

已新增可选 `rewrite/geography.json`，由 API 3 的扩展清单引用，是通用入口。以下配置结构现已支持：

```json
{
  "schema": 1,
  "maps": [
    {
      "map": "author.map",
      "width": 100,
      "height": 80,
      "baseTerrainSha256": "<对应基础地形BIN的SHA256>",
      "terrainOverrides": [
        { "column": 30, "row": 20, "type": "impassable_mountain" },
        { "column": 90, "row": 60, "type": "impassable_sea" }
      ]
    }
  ]
}
```

示例坐标不对应东亚或日本的实际地块。地图使用已注册标识，宽高和基础地形摘要用于防止把旧格号套到新地图上。

作者流程：选择地图 → 批量涂绘/由地理区域生成格清单 → 将山口与航路恢复为普通可通行类型 → 导出配置 → 导入校验和连通检查。首版提供可复用的离线配置生成/校验工具及最小示例 Mod，不以新增可视化编辑器作为前置条件。

- 默认复用内置类型及素材；提供按类型替换贴图、普通/高清图和地块信息图标的配置入口，具体字段在实现时依现有 manifest 约定落定。
- 经纬度山脊/海域多边形属于制作源；运行时使用已解析的格子属性，不逐帧计算地理几何。
- 越界、重复坐标、未知类型、海陆冲突、摘要不符及实体冲突均拒绝导入；批量源重叠须在生成阶段解析并输出最终唯一记录。
- 实际启动、重新开始、Mod导入、导出、停用及重新启用都必须经过相同合并流程。缺少扩展文件时为旧行为；声明了新扩展但文件损坏时不得静默放行。
- 为新能力声明明确的引擎/API能力要求，防止不支持的旧运行时将禁行配置当成普通地形。沿用并按需升级现有扩展/包版本机制。
- 配置、类型规则和相关素材加入内容摘要；通行规则进入逻辑指纹。图形替换与逻辑变化按现有指纹约定区分。
- 现代地图导入导出和存档均保存禁行语义，不能只存在前端 manifest；旧12字节 BIN 保持原格式。导出纯旧版地图时，对新禁行语义给出明确不兼容结果，不能悄悄丢弃。

## 5. 首批应用：当前东亚喜马拉雅

在当前158×136、约42公里格距的东亚图上配置，保留城市 ID、主体地形和已配置设施。只依据喜马拉雅主脊划禁行带，不把整个西藏高原、所有高山或全部藏南自动封锁。

现有 Himalaya 制作线从73°E延至97°E，是概化绘图线，不能直接把其100公里缓冲区全部设禁行。实施前用可靠山脊/地形参考核对主脊、河谷、两端绕行及城址，输出逐格范围图。

按用户补充，山口位置优先参考现实地理与历史通道。先核对真实山口、两侧河谷及历史交通路线，再落格选择，不为凑通道数量在山脊上任意开口。初步比较以下方向，最终数量由史地依据和当前格距决定：

| 候选通道 | 取舍 |
| --- | --- |
| 普兰—里普列克方向 | 西段通道候选，核验与两侧现有道路/城市的连接及时代适用性。 |
| 吉隆方向 | 核对吉隆古道及通往尼泊尔的两侧河谷，作为中段通道候选。 |
| 聂拉木—库蒂方向（樟木一带） | 与吉隆方向比较古道位置和网格可分辨性；区分历史路线与现代公路线，不能把现代口岸状态直接当作历史依据。 |
| 亚东—乃堆拉／则里拉方向 | 核对连接锡金方向的实际山口和历史交通线；相近路线在粗网格上可合并表达，不凭名称数量开多个相邻缺口。 |

以上为待核验候选，不代表已经完成历史考证，或所有时代均适合军队通过；采用前记录来源、坐标、适用时期、路线性质及两端连接。商旅/驮运可通过与大军重装备可通过分别说明，现代开放或关闭状态不决定跨时代基础地形。相邻山口在约42公里格距下无法分别表达时合并为一条有来源记录的概化通道，并记录落格位移。

山口必须是一条贯穿禁行带、连接两侧可通行区域的连续格链，不能只留一个孤立普通山地格。优先1格宽，因格距/拐弯确需2格时局部放宽；通道仍按普通山地规则移动，不改成平原。下一步范围示意须标出真实山口位置、游戏通道格链和对应史地依据，方便逐处核对。

验收关注：非山口路径不得六邻接漏穿；关闭某山口后应失去该局部越脊通路，同时区分可接受的山脉端部绕行。核查拉萨、日喀则、江孜、普兰等实际城点及设施冲突、喜马拉雅两端和河谷，不把塔什库尔干/瓦罕等其他山系顺手改作本任务内容。

## 6. 首批应用：规划中的日本大图

构图保持用户确认的15°及左界收窄版，南端至冲绳，不重新扩回宫古/八重山。按用户补充，直接使用该参考图已经表达的海底地形差异设计：沿大陆架外缘及向深海盆、海沟的明显过渡勾绘分区，将指定深海区设为 `impassable_sea`。不另以固定离岸公里数作为主要划界依据。

- 以当前图的浅色陆架、坡折与深色海盆/海沟为视觉依据人工勾绘地理多边形，再映射至日本图的投影和网格。颜色辅助识别地形分区，不直接用某个RGB阈值冒充精确水深线。
- 深海区按图中实际形状延伸，不画等宽沿岸带；大陆架与岛屿周边浅海依地理连续性保留。地图内朝鲜等大陆沿岸同样按图上地形处理。
- 宗谷、津轻、根室、关门、对马及濑户内海入口，以及北海道—北方四岛、九州—种子岛/屋久岛—吐噶喇—奄美—冲绳的通路，在勾区落格后核对是否被意外截断，不预先用虚构宽航带取代实际海底地形。
- 若地理分界在粗网格上误封海峡或岛间通路，仅对具体位置做有记录的局部修正；对实际深水但需通航的通道单列例外，避免把“深水”机械等同于所有位置都禁航。港口出口保留必要水域，修正不得泛化成整片远海解禁。
- 禁航边界由整格规则决定；视觉可有短距离色彩过渡，但格心状态和边界必须可读。航路留白不能被深色渐变覆盖得像禁航格。
- 先交付带网格的可航/禁航范围示意，检查岛屿、城市港口与航路，再进入正式日本底图制作。

## 7. 默认贴图规划

山地取原版 `mountain_1..6` 六种轮廓，在原风格上做更高山体、冷灰岩面和峰顶积雪；保留暗部、纸面色调及透明边缘，雪集中于高处，避免把整座山涂白。普通高山保持可辨，雪山形成新的禁行等级。提供普通/高清对应版本和地块信息图标。

海洋基于原版海面生成更深、略低饱和的蓝色，保留原版质感与稀疏浪花，不新增密集波纹。海面本身必须变深，不能只把浪花精灵压暗。与东亚已采用的透明陆地/不透明水面分层兼容，处理地块遮罩、岸线、相邻禁航格接缝及分块重叠。

新素材使用独立名称并扩展图集，原版图块坐标与像素保持；Canvas/Pixi、远景/近景、普通/高清均覆盖。先提供普通山地—高山—禁行雪山，以及普通海洋—禁航海洋的并排样张，再确定雪量和暗色强度。本轮不生成素材。

## 8. 存档、接口和性能

- 旧地图/Mod没有新字段时保持原行为；未知禁行类型必须报错。
- 新运行时读取旧地图/存档时，为缺失禁行字段显式补 None，并核对原内容指纹；是否升级 map/save 版本，依最终字段契约统一实现和测试，不只修改版本常量。
- 更新东亚禁行配置会改变地理规则和逻辑指纹；已有东亚对局不强行套用新禁行带，也不移动或删除旧档部队。新开局使用新图；旧档维持旧资源版本或另行设计明确迁移。
- 全量状态、增量状态、重启恢复、地图导出和存档往返均包含类型与禁行原因；地块信息可见且没有可执行的移动/部署入口。
- 对 AI 连通分量、距离缓存和战略查询的键/失效规则纳入禁行属性；保持每次邻格判断为常量开销。用既有东亚和约8.6万格大图夹具比较内存、寻路与过回合，避免每格对象或逐帧多边形判断。

## 9. 实施顺序与验收

1. 先完成通用类型、统一通行/落点校验和最小地图测试；两种地块均能在任意地图使用。
2. 接通地理扩展的实际加载、Mod导入、内容指纹、现代地图及存档往返，提供文档和两个独立地图的最小示例 Mod。
3. 交付原版派生贴图样张与普通/高清资源，验证 Canvas/Pixi 和所有缩放下的边界。
4. 对当前东亚做喜马拉雅禁行带与候选山口示意，审定后才写入正式东亚数据。
5. 对日本参考构图做近海/远海禁航网格示意，审定后随日本大图制作应用。
6. 已授权实施源码、地块、素材与隔离验证；发行打包及现有玩家服务迁移不在本次交付内。

关键检查包括：步兵/骑兵/炮兵/地理技能/舰船/运输/高行动力/超额进入均不能越界；AI与手动结果相同；山口两端连续；日本岛链与港口航路连通；招募、部署、空降、传送、召唤和剧本生成拒绝非法落点；占领/辖区/胜利规则不把禁行区当必占目标；无扩展的既有地图行为一致；Mod打包和读档不丢规则；新旧显示路径无缺图、接缝或画面空洞。
