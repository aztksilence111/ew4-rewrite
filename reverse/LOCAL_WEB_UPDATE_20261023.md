# 本地 Web 运行版本更新

2026-10-23。用户指出本地 Web 没有远景省略兵模和国旗，要求直接更新正在使用的本地版本。

## 原因与处理

- `5191` 原服务使用 `build/release-0.2.16-20261023/web` 内旧发行文件，实际返回 `battlefield.js?v=20261023.2`，没有远景分流。项目启动器会复用该端口已有服务，因此只更新源码或打开独立预览无法更新用户的本地服务。
- 从当前源码重新发布 Windows x64 独立 Web，隔离构建于 `build/local-web-update-20261023/staged`，构建及 31 份 Chrome70 兼容资源生成通过。
- 已更新上述本地运行目录的应用文件并重启原 `http://127.0.0.1:5191/` 服务，保留原存档目录和当前对局。该目录名沿用旧名，但内部运行文件已更新，不能再作为原 0.2.16 发行包校验副本。
- `Open-Web.url` 从历史端口 5184 改为 5191。没有修改发布 ZIP、APK 或远端 Release。
- 更新前完整备份玩家档案到 `build/local-web-update-20261023/profile-before`，变更的原运行文件备份到 `runtime-before`。自动档在重启前保存当前对局，更新后载入；手动存档和内容包保留。

## 验证

- `deployment.json`：当前征服第一回合、252 支部队，剧本、版本号、回合、阶段、玩家、行动国、地块、势力和部队状态一致；导航资格字段允许使用新版重新计算。普通及兼容脚本均含远景分流。
- `browser.json`：在真实 5191 服务读取当前对局，桌面 1280×720、手机 844×390 共 8 场景、28 项验证通过，浏览器错误 0。相对缩放 0.48/0.28 时兵模、国旗、姿态计算调用均为 0；1/0.66 时恢复。截图 `desktop-far.png`、`phone-far.png`，像素非空。
- 浏览器核验只读取并呈现已有对局，没有开始新局、行动、保存或加载请求。更新步骤的保存和加载另见部署脚本。
- 首次复制遇到短暂程序集占用，停止后恢复复制完成；兼容脚本验证去掉了会被转译器移除的注释匹配，改查实际远景条件与返回分支，最终部署错误 0。

证据和可恢复备份均在 `build/local-web-update-20261023/`。用户原浏览器需刷新页面，才会载入新脚本。
