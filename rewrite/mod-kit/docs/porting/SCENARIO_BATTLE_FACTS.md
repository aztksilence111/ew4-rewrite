# 可选战果记录

2026-11-16源码接口。由Mod主动订阅，不订阅的剧本不增加记录；不要求修改世界存档格式。状态均使用现有`ExtensionState`，随存档恢复。此接口只记事实，响应阈值、阵营范围及剧情由Mod决定。

## 开局订阅

在第一步战斗前，用事件`state`效果写入以下键：

| 键 | 值与作用 |
| --- | --- |
| `scenario/battle_facts/faction/<实际国家ID>` | 作者指定的正整数阵营标记；不是国家数组下标，国家切换后不变 |
| `scenario/battle_facts/watch/cell/<格索引>` | `1`，观察该格的军事占领 |
| `scenario/battle_facts/watch/unit/<单位ID>` | `1`，观察该单位真正销毁时的所属 |

动态建立国家后也须登记阵营标记。未登记国家记为`0`，不能将其推定为任意一方。

## 宿主输出

正常移动引发领土变更时，已订阅的格写入`scenario/battle_facts/capture/<格索引>/`下的`from`、`to`、`round`、`count`，分别为之前所属阵营、夺取方阵营、回合和累计变更次数。单次移动可能改变多个格。政治`cells_owner`转交、投降及直接撤除单位不生成军事夺取记录。`count`是次数，不能当作不同据点数。

实际单位销毁经`WorldDeaths.Remove`时，已订阅单位写入`scenario/battle_facts/destroyed/<单位ID>/`下的`owner`、`round`、`cell`。`owner`是销毁时的阵营，不能因原始编制而把已改旗部队继续算成原方战损。作者强制`destroy_unit`也会记录；`unit_remove`撤离不记录。单位ID不能复用于需要另算损失的新部队。

当前据点目标必须同时核对当前归属与记录；旧夺取事实在政治转交后仍作为历史保留，不能单凭旧记录认定现在仍控制据点。需要更严谨的政权变更含义时，由Mod额外记录状态。

## 兼容边界

历史存档缺乏战果记录，不能从消失单位和当前归属反推成实际战果。采用本接口的新剧情建议新开局；不要把旧档无损读入误称为补齐历史事实。只读目标可用`state`与`cells_owned`组合，见[暂停目标](PAUSE_OBJECTIVES.md)。
