# BGM 播放复查与故障恢复

2026-10-27。用户说明 Windows 网页和 Android 安装包均有打不开 BGM 的反馈。本轮修复源码和共享兼容前端，未打 APK 或正式发布。

## 确认的问题

- 原 `music.js` 在任意媒体 `error` 后将 `failed` 永久设为 true。后续点击、调音量、回前台均只执行暂停，不重新加载。同曲目的菜单切换也不会清除此状态；必须切换不同文件或刷新页面才能偶然恢复。新增回归在原实现上因不存在恢复路径而失败。
- 播放 Promise 尚未结束时切后台再回来，恢复请求可能被旧 `pending` 拦住。原 finally 只释放 pending，不执行被拦住的恢复；已补恢复请求及旧曲目异步结果隔离。
- 本地 Windows Web 使用 localhost、127.0.0.1、[::1] 时，每次刷新将音乐及音效音量设为 0，即使此前保存过非零音量。此为既有静音要求，本轮保留。需要在设置中重新调高音乐；Android 的 ew4.local 不命中该规则，不能用它解释手机反馈。

## 修复

- 媒体错误及播放超时允许最多两次自动恢复；重试耗尽后，后续用户操作、调音量或回前台仍可重试，避免永久无声。普通点击失败重试有冷却，防止连续点击造成请求风暴。
- 正常播放继续使用原 MP3 地址。失败时改由 fetch 完整读取当前内容版本的 MP3，再交给 Audio 播放本地 Blob，提供绕过原生媒体请求及字节范围依赖的备用路径。CSP 仅补 `media-src 'self' blob:`。
- 慢加载、旧曲目请求、销毁及后台恢复受独立代次保护；备用 URL、请求、定时器在换曲或销毁时释放。15 秒未开始播放或请求未完成则进入有限恢复。
- 音量滑块显式解锁播放并请求恢复；保留首次交互、音量为零和后台暂停规则。保留 `lastError` 和控制台警告，区分 HTTP、媒体、超时及手势拒绝。
