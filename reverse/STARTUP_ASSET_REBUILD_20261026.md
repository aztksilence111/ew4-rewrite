# Android 与 Web 启动资源检测及规则重建

2026-10-26。按用户确认：每次启动检查内置原版资产，无变化复用结果，有变化才重建。两端共用实现；未发布新版本、安装手机或修改用户提供的 XML。

## 行为

- 对运行时资源计算 SHA-256，比较构建时自带的 `runtime-content.json` 和本地校验缓存。缓存同时绑定校验实现版本；代码升级会重新核验，但资源身份与变更配置的存档目录不因重新编译而改变。
- 首次启动解析所有原始 XML、BTL、地图 BIN，检查全部地图格、规则和显示资源引用。与已验证发行清单一致的原版无需重新生成规则，也无需模拟全部场景开局。
- 无变化时只检查输入哈希及生成文件的完整性，跳过转换和深层场景校验。
- 修改旧 XML 导致来源哈希不匹配时，调用现有转换器生成配套独立 JSON 和真实来源哈希；同步兵种展示数值、将领、建筑、首都及国家来源信息。未改 XML 的直接 JSON 配置保留。
- 合法 BTL 加入或修改会重新校验；新征服注册到选择页。地图 BIN 变化会更新地形覆盖图层；同网格尺寸的地理配置重新绑定并再次校验陆海属性与格子引用。修改地名位置 XML 时同步显示数据。
- 变化后的候选配置执行全部场景开局及资源引用校验，成功后再提交独立缓存；生成过程中检测到源目录继续变化会拒绝提交并提示重试。损坏缓存从原资产重新生成。
- 不替用户纠正非法数值。XML 语法错误、损坏 BTL/BIN、海洋消耗 0、缺失的显示配置等均给出文件及错误；失败不覆盖已有成功缓存，也不混用上一次配置和本次原始文件。
- 修改玩法资源后使用 `saves/builtin/<logicRevision>` 独立账户/存档，避免旧原版账户内容指纹不符阻止进入；原账户和存档完整保留。还原资源后回到原目录。已安装 Mod 的独立校验和存档机制保持。

适用范围为两端打包的运行时资产。新增种类、全新地图贴图、动画等仍须提供引擎要求的配套资源；启动转换不会实现未知原生机制，也不会生成缺失的美术资源。

## 接入

- `rewrite/Ew4.Mods/StartupAssets.cs`：资源指纹、原格式校验、转换、展示数据同步和验证缓存。
- `rewrite/Ew4.Mods/ContentValidation.cs`：与 Mod 导入共用场景和资源引用校验。
- `rewrite/Ew4.Mods/ModFiles.cs`、`ModStore.cs`：变更配置的存档隔离，原版资源身份保持。
- Android `MainActivity` 在后台准备资源，显示等待指示，成功后加载 WebView；失败显示错误和重试/退出。异常不会被 Lazy 永久缓存。APK 增加自带资源参考清单。
- Web 服务启动后台准备资源，请求等准备完成后进入游戏；失败返回 HTTP 503 和具体错误，页面可重试。游戏已正常运行时修改磁盘资源，需要重新启动 Web 服务；仅刷新正常页面不触发热重建。
