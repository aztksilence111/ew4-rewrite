# R 版暂停目标栏规划

日期：2026-10-25。状态：已实施，按用户后续修正以暂停菜单居中为布局前提。实现与验证见 [实施记录](../reverse/PAUSE_OBJECTIVES_20261025.md)，实际接口见 [作者文档](mod-kit/docs/porting/PAUSE_OBJECTIVES.md)。下文保留原设计依据，接口收敛和刷新方式以实施记录为准。

早期独立样式示例位于 `build/pause-objectives-style-20261025/`；现使用 [真实游戏预览](http://127.0.0.1:5561/)。暂停固定高度导致底部按钮越界的问题已修，目标栏和原有菜单独立布局。

## 1. 需求与展示

在战役、征服的暂停界面增加左侧目标栏，从屏幕左边缘向右伸出。显示当前生效的通关条件、失败限制，以及不同胜利评价的达成条件。目标栏提供 Mod 作者可配置的 UI 接口。内容有变化才更新；过回合但内容没有变化时不刷新。

用户补充：原版回合数影响满星等不同胜利结果，也须在此栏说明；择一关系直接写明，不能把所有目标画成全部必做。

- 打开暂停时目标栏滑入，恢复游戏时收回；正常战场不常驻。
- 背板左端贴屏幕边缘，使用现有原版材质、字体、目标圈和星图；按后续手机反馈，目标栏取消摄像头安全区避让，顶栏和底栏也从左屏边开始，长内容通过滚动查看。
- 通关条件、失败限制、胜利评价在同一栏内分区，按行排版；复合条件直接显示“满足任一”或“全部满足”，嵌套时保持分组。
- 普通行显示条件文字与状态，必要时显示目标数量；评价行显示星级对应的回合区间，以及“仍可达成 / 已无法达成”。不把尚未通关时的评价显示为已获得奖励。
- 默认不显示逐回合递减的倒计时、当前回合数、实时奖励预估。固定期限一直可见；仅在条件状态、评价档位或规则变化时更新对应行。
- 内容过长使用纵向滚动条，支持滚轮和触摸；展开、更新保留有效滚动位置，无变化时保留同一批节点。

示意内容，具体文字、数值及条件组合以当前剧本实际规则为准：

```text
胜利条件
满足任一
  消灭全部参战敌国
  清除敌方全部目标

失败限制
  保有己方目标
  不得超过第 N 回合

胜利评价
  5 星：第 M 回合及以前通关    已无法达成
  4 星：第 ... 至 ... 回合通关  仍可达成
  3 星：第 ... 至 ... 回合通关  仍可达成
```

本示意只说明排版。没有目标胜利分支的剧本不显示该项；不同模式及多人不得套用同一份固定文案。已失去满星机会与本局失败是不同状态。

## 3. 胜负与评价模型

后端输出只读的暂停目标视图，前端负责渲染，不在 JavaScript 中重新实现胜负或星级公式。

### 3.1 通关与失败

1. 优先读取当前 `ScenarioVictory`，其次读取本局自定义胜负规则，最后解释原版默认规则。
2. 保留 `all/any` 树结构与稳定条目 ID，明确“全部满足 / 满足任一”；原版条件也转换成等价的展示树。
3. 回合上限、生存、失败树和胜负同时成立时的优先级必须一并说明。单项完成不等于整局已赢；仍以正常判定点与正式结算为准。
4. 地格和部队目标沿用真实归属、外交与中立判定，不能用地图颜色推测。目标转移、单位损失、国家灭亡、宣战及同盟变化均可能影响提示。
5. 剧情替换条件后，整组切换到新阶段；恢复默认条件也必须恢复正确提示。待选择弹窗内尚未确认的规则不提前显示为生效。
6. Lua 条件优先显示当前规则描述或作者提供的条件文字；没有安全的结构化结果时显示“特殊条件”，不编造百分比或完成状态。打开暂停不得额外执行胜利脚本。
7. 本地多人使用当前被展示的人类席位视角，AI 行动期间保持最近的人类视角。沿用战役共享胜利、征服独立胜利及中立限制；不得把单人失败树套到整局多人。

### 3.2 满星与其他评价

- 回合影响星级的规则与通关条件分别呈现，但可在同一栏交叉说明，例如“超过满星期限，仍可继续争取较低评价”。是否还能通关取决于当局实际回合上限。
- 从 `BattleSettlement.Stars(round, minimumRatingRound, highestRatingRound)` 推导各星级的真实整数回合区间，不自行按均分回合猜分档。核对满星边界包含当回合、降档边界以及最小评价边界。
- 星级区间与实际允许通关的回合范围相交；不可到达或空区间不伪装成可选结果。原版 `Header[12]` 同时参与回合限制与评分，不能展示超时以后仍能通关的假分支。
- 显示所有实际可达评价档位，过期档位保留并标记“已无法达成”。默认只显示固定区间和可达性，普通回合推进而尚未跨分档时内容完全不变。
- 动态胜负规则若取消或修改回合上限，星级仍按当前宿主实际结算来源展示；不能假设 `victory_rules` 会同时改变评分门槛。
- 征服同样读取宿主实际返回的星级规则；征服奖励是另一套算法，本次默认不加入资源/将领驱动的实时勋章估算。
- 多人当前使用独立各国结果窗口，不凭单人星级公式虚构其评价。没有该评价时隐藏该分区，显示实际胜者规则。
- 若未来增加新的胜利结局或评分规则，应由其规则提供对应展示数据；本接口允许分组展示，但纯 UI 配置不能创造实际结局或修改得分。

## 4. 有变化才刷新的机制

区分“检查是否需要更新”“展示内容变化”和“重建 UI”。世界版本变更仅代表游戏发生动作，不能直接作为目标栏版本。

拟采用惰性缓存：目标栏隐藏时只记录与条件有关的失效标记，打开时按需生成最新视图；可见期间若已有在途命令提交，再按同样机制更新。没有相关变化时直接复用缓存。

处理链：

```text
动作/剧情/回合提交
  -> 按当前目标依赖判断是否可能改变展示
  -> 相关变化只标记待核对；隐藏期间合并多次变化
打开暂停 / 可见时收到已提交变化
  -> 必要时生成候选展示模型
  -> 与缓存按展示字段比较
  -> 相同：复用原内容版本与节点
  -> 不同：增加内容版本，仅更新变动条目
```

依赖与刷新口径：

| 变化 | 是否可能更新 |
| --- | --- |
| 普通回合推进，无回合目标、无评价分档变化 | 不更新 |
| 越过满星或其他星级区间边界 | 更新评价可达性，通关内容未变则复用 |
| 到达生存回合、资源门槛或超过失败上限 | 对应行状态变化才更新 |
| 普通移动、非目标单位受伤、与规则无关的招募 | 不更新；若自定义条件确实依赖该项则按其依赖处理 |
| 目标格归属、目标单位、指定部队、国家存续、外交改变 | 按关联条件核对，有显示差异才更新 |
| 剧情换阶段、切换扮演国家/人类席位、读档、重开、切换 Mod | 重新确定上下文并生成当前视图 |
| 窗口尺寸、横竖屏、字号、布局/素材配置变化 | 只做必要的布局或样式更新；不伪造目标进度变化 |

实现约束：

- 不增加定时轮询、不把目标更新塞入每帧地图绘制、不在每个回合无条件清空列表。
- 固定回合条件按其真假阈值建立依赖；评价按分档边界建立依赖。作者若选择显示当前回合或倒计时，该字段变化才属于真实内容变化，默认样式不启用。
- 有数量显示时，数量变化属于内容变化；只显示完成状态的行，不因无关内部计数变化刷新。
- 自定义资源条件默认显示门槛与满足状态；跨门槛才变，避免每次生产/消耗都改字。
- 条件依赖必须保守正确。不能安全缩小依赖的脚本/复杂条件标记为候选失效，但仍须通过展示模型比较，且不额外执行脚本。
- 若要显示脚本真假，须复用正式判定时已获得的只读观察结果；没有执行到的短路分支不得猜成未完成。首版允许仅显示作者文字。
- AI 批量提交可合并隐藏期间的变化；暂停不再驱动 AI。已有在途动作完成后展示最终已提交状态。
- 缓存上下文包含 battleId、内容版本、规则、观察国家及语言；不同战局/席位不串用。内容版本与世界 revision 分离。
- 全量状态必须提供完整目标快照；增量可只给独立内容版本，变化时携带新快照。缺缓存或错基线时按现有机制恢复全量，不能把省略字段误作清空。
- 暂停开合只改变可见性和滑入动画。无内容变化时重复打开复用已有内容节点；布局变化可单独重新排版。

## 5. Mod UI 接口草案

接口 `pauseObjectivesPresentation` 已在 `rewrite/extension.json` 注册并指向独立配置文件。首版采用受约束的外观配置，字段和范围以 [PAUSE_OBJECTIVES](mod-kit/docs/porting/PAUSE_OBJECTIVES.md) 为准；下表的完整布局树和绑定是后续扩展设想，当前不支持。

```json
{
  "pauseObjectivesPresentation": "rewrite/pause-objectives.json"
}
```

沿用已有精确剧本 ID 优先、`*` 全局默认的匹配方式，分支/隐藏关按实际 ID 配置。

拟提供以下能力：

| 配置 | 能力 |
| --- | --- |
| `layout` / `rowLayout` | 边栏与重复目标行的安全原生布局树，缺省使用内置边栏 |
| `bindings` / `rowBindings` | 绑定标题、通关树、失败限制、评价列表，以及条目文字、状态、进度、星图与分组关系 |
| `title`、分区标题、状态文字 | 文字或字符串表键 |
| 宽度、高度上限、内边距、滑入时长 | 受范围约束并参与响应式适配；边栏始终从左边缘伸出 |
| 背板、边框、状态图、星图 | 引用已登记图集/合法图片资源，允许替换材质 |
| 条件说明映射 | 覆盖指定条件路径的显示文字，补充脚本提示；覆盖文字不改变条件逻辑 |

保持以下边界：

- 条件 ID/路径须稳定，便于文字覆盖、行复用和阶段变化后的正确匹配；不能只用中文文字当键。
- `all/any`、实际失败限制、星级区间和状态来自后端。作者可以调整排列与外观，默认仍保留关系和关键限制，避免布局造成误读。
- 复用现有布局树与图集校验规则；允许列表重复行、自动换行和纵向滚动，不执行作者 JavaScript/HTML，不支持任意 CSS 注入。
- 新根布局按边栏坐标工作，不继承详情窗口专用的 27 像素标题偏移；旧结算/说明窗口布局语义保持兼容。
- 缺绑定、歧义路径、错误类型、未知图片、越界文件、重复键等由导入/打包校验拒绝；无配置回退默认栏。
- 配置进入现有资源收集、Mod 导入导出和指纹流程；实施时核对是否触及旧存档逻辑指纹，不为纯展示缓存新增存档格式。
- 本功能的“战局胜利目标”与指挥部 `objectives` 任务/成就接口分别命名与注册，避免混淆。

## 6. 屏幕布局与输入

- 暂停菜单始终在实际屏幕正中心，不为目标栏移动。
- 宽屏：左边栏根据暂停菜单左边界缩窄，留出间距；长内容在目标栏内纵向滚动。
- 窄屏/竖屏：左侧余宽不足时，目标栏贴左边缘收短至暂停菜单上方；暂停菜单仍在屏幕正中。
- 屏幕很矮时压缩区间留白与菜单间距，并增加可用滚动范围；返回、保存、设定、重开、退出均可操作。
- 暂停栏、遮罩和滚动事件不穿透战场。打开设置/详情时沿用现有层级，目标栏不抢焦点或挡住上层窗口。
- 桌面、Android 共用前端；测试触摸滚动、设备安全区、系统返回键和快速开合。动画只改变 transform，不持续触发内容渲染。

## 7. 实施阶段与验收

1. 先完成规则展示模型及星级区间投影，覆盖原版、动态规则、外交和多人视角；用现有胜负/结算结果校验一致性。
2. 接入独立内容版本、依赖缓存与全量/增量契约，增加诊断计数：候选生成、内容版本增长、行更新/重建次数。
3. 实现原版风格左侧栏、联合布局和开合动画，再注册可配置布局、资源、行模板与条件文案接口。
4. 提供作者文档和可打包示例，包含原版择一关系、不同星级期限、复合条件、多阶段与脚本描述。
5. 验证后保存证据，再更新短锚点与日志；是否双端打包按后续实施指令安排。

关键验收：

- 默认目标开启/关闭、目标归属策略、敌国灭亡、无目标场景、外交及中立变化，提示与实际判定一致。
- `all/any` 嵌套、失败优先级、动态替换/恢复、待确认选择、存读档、脚本说明正确。
- 各星级区间首尾与 `Stars` 完全一致；满星期限当回合、后一回合、各降档边界、回合上限当回合及后一回合重点对照。
- 在允许降星继续的场景，超过满星期限仅评价行更新；仍按实际通关条件继续，不提前显示失败。到真正失败上限时按规则显示。
- 无变化过回合、无关动作、重复打开暂停：内容版本不变、内容节点不变、内容更新计数为 0。
- 占领目标、丢失指定部队、资源跨阈值、越过评价档位、换阶段：只在有显示差异时更新，隐藏期间多次变化合并成最新视图。
- 全量/增量恢复、AI 批量暂停、同剧本重开、换玩家、换 Mod 不串缓存；暂停操作不增加 Lua 调用，不改变 RNG、胜负或奖励。
- 至少覆盖 1280x720、829x405、405x829 和更窄屏幕；文字不溢出，目标栏与菜单无重叠，滚动不穿透。
- Web 与 Android 共用路径构建、现有暂停/多人/结算回归，以及浏览器截图与实际 DOM 更新计数通过后，才标记已实现。

首版已实现规则投影、独立版本、惰性缓存、内容行复用、居中避让和 Mod 展示配置。隐藏时不请求、不计算；新世界状态在下次打开时按需生成候选，展示字段相同则不更新 DOM。尚未做按每个条件依赖细分的候选生成优化；不影响“内容不变不刷新”的要求。交付范围为本地测试 APK，真机验证另行记录。
