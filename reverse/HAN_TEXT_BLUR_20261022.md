## 当前实际实现

1. 普通界面经过 `original-ui.js::TextRenderer` 生成文字 Canvas。`glyph` 优先查询指定字体的原版 PNG 字形及 manifest 中的坐标、偏移和步进；未找到时还会查询四套中文 HD 字库。
2. 原版位图中仍找不到的字符，用 Canvas `fillText` 绘制内置 WOFF2：霞鹜文楷优先，随后 Noto Serif SC、Jigmo 三平面及 Unifont 补字。分片按需加载并重画，不依赖系统字体。同一句话可以包含原版位图字与后备字体字。
3. 当前 manifest 四套中文 HD 字库高度为 24/24/26/32 像素，字形记录数分别为 1231/845/399/370；字形存在交集，不能把记录数相加当作独立汉字数。
4. `element` 默认 `rasterScale=1`，画布以排版像素绘制，CSS 宽高为画布的一半，再随界面缩放。菜单以 568×320 为基准；多数界面文字调用没有按最终界面倍率及 `devicePixelRatio` 提高画布分辨率。部分标题还会额外 CSS 放大。
5. 城市名也经过文字渲染器，地图绘制另传 1～4 档密度；中文地理标注有独立绘制路径，当前缓存 `density=1`，陆地区域优先 Noto Serif SC、海域沿用默认字体链。战场主画布的高清 DPR 设置不等于全部文字缓存同步提高分辨率。
6. 战斗伤害数字另走原版 `font_fight_num_hd.png` 位图路径。

源码依据：`rewrite/Ew4.Web/wwwroot/original-ui.js` 的 `glyph/layout/element`，`app.js` 的 `sizeUi/cityLabel`，`battlefield.js` 的地理标注及城市标签缓存，`original-ui.css` 的文字画布和标题缩放。

## 待核查方向

- 原版小尺寸位图字放大、固定分辨率文字画布放大、非整数倍率插值，都可能让笔画发虚；字体资源为 HD 不等于任意缩放后都清晰。
- 后续应区分菜单/对白/城市名/地理标注，并对照实际 CSS 尺寸、画布像素、设备 DPR、高清开关及原版同场景，确认模糊来自哪条路径。
- 后续按用户指定的全内置字体方案处理，并保持字体风格一致和缺字覆盖；当前不修改代码、不构建或发布。
